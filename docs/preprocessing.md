# 收集曲目的预处理

预处理解决「作者原始包 → 标准曲目包」的格式差异。窗口中的“预处理曲目”已经可用，读取配置的待更新目录，将工作副本写到发布工作区；不会修改收集目录、active 或本地/远端服务端。

## 已实现规则

| 原始情况 | 处理方式 |
| --- | --- |
| 曲名外层目录 / 英文内层目录 | 递归寻找实际含 AFF 的目录；只在归属唯一时合入外层的 songlist 或媒体文件 |
| 目录名与 songlist.id 不同 | 采用合法 ID，仅将工作副本目录改为该 ID 并报告 INFO；不改原目录 |
| 缺少、空或不合法的 ID | ERROR；不采用目录名、不猜测 ID，等待人工补全 |
| `slst`、`slst.txt`、`slst.json` | 与 songlist 系列一样识别，统一输出 UTF-8 的无后缀 `songlist` |
| 大小写不同的标准资源名 | 归一 AFF、基本曲绘和音频的名称；保留自定义背景标识 |
| 单曲 JSON 片段末尾逗号、数组或对象尾逗号 | 在字符串之外移除这些逗号，报告 WARNING；不修改曲名中的逗号或引号 |
| 完整单曲对象之后多出闭合括号 | 只在完整对象已可解析、尾部仅有多余闭合符号时恢复，报告 WARNING；不猜测缺失字段 |
| UTF-8 BOM、UTF-16 BOM、GB18030 文本 | 读取并转为 UTF-8 输出，报告使用的兼容编码 |
| 只有主曲绘（JPG / JPEG / PNG） | 整理为真实 JPEG 的 base.jpg，并生成 384×384 的 base_256.jpg；数字独立曲绘也可补对应缩略图 |
| 已经是 1080_base.jpg / 1080_base_256.jpg | 在标准原始包副本中还原为 base.jpg / base_256.jpg，供后续 bundle 准备统一处理 |
| base.mp3 / base.wav 或数字独立音频 | 使用已配置或 PATH 中的 FFmpeg 转为完整 Vorbis OGG，保留源文件 |
| 主音频名不规范，但只有一份未命名用途音频 | 在缺少主音频时映射为 base.ogg，并显式报告；多份或冲突则待人工选择 |
| AFF 中引用的 `*_wav` 特殊音效、与主音频并存的额外 WAV | 不复制到标准副本，因而两侧都不导入；报告 WARNING，保留 AFF 引用供人工处理 |
| Arcade 子目录 | 忽略整个子树，不把编辑器工程当成额外难度 |
| 编辑器默认空 AFF | 按内容排除，不根据文件大小判断；已声明但没有实际谱面的难度 rating 统一为 0 |
| 原始 version 不同、空或缺失 | 曲目顶层统一使用界面本次导入 version；不新增或覆盖难度 version；设置 remote_dl=true |

首版标准 ID 限定英文、数字、下划线和连字符，并排除 Windows 保留设备名，以便输出目录可移植。ID 不符合该规则时不会自动删字符或替换为另一首曲目的 ID。

## 空谱与占位谱的区别

检测器只识别已知 AFF 头和纯 `timing(...)` 内容。即使超过 1KB，纯 timing 模板仍可排除；即使不足 1KB，只要有 tap、hold、arc 或其他未知事件语法，就不会被当成默认空谱删除。

例如：

```text
AudioOffset:0
-
timing(0,100.00,4.00);
```

空谱只从本次工作副本排除，原文件保留。若包里只剩默认空谱，该包记为跳过；若有其他有效谱面，则只导入有效谱面文件。已声明的其他 ratingClass 不删除，若输入和已有服务端都没有该难度的实际谱面，将 rating 统一为 0（包括原来的 -1、0 或其他占位值）。不为未声明的难度编造条目；输入占位描述不能覆盖已有真实难度的元数据。

这不改变服务端要求 0–2.aff 的规则：缺失槽位的占位谱由后续下载资源准备阶段统一补齐，已有真实谱面优先保留。输入作者模板不等于一次真实难度更新。

## 缺少 songlist 信息

若 active 的总 songlist 中存在**完全相同 ID**，可继承缺失的字段，并为实际存在的谱面继承该难度的已知描述。输入已填写的值保留，后续仍由总表合并报告冲突；不会在预处理时悄悄覆盖它们。

全新曲目的曲名、作者、BPM、预览区间、背景、实际难度定级等缺失时列出字段清单，由人工补全。version 始终由本次导入配置覆盖，不要求原始包提供；idx 留给总表合并阶段分配。缺少整份 songlist 时报 ERROR，即使目录名能匹配已有总表，也不据此猜测曲目身份。

以下情况不自动修复：

- 未加引号的 `DJ`、错误转义的引号等语义不明确或语法错误。
- JSON 重复键、多份 songlist/slst、多曲条目混在同一个包。
- 多个来源使用相同 ID（包含仅大小写不同）、多个音频争用 base.ogg。
- 上层一份 songlist 可能对应多个子目录。
- AFF 文件名不能确定为 0–4，或提供了真实谱面却缺少对应难度描述。
- rating 为字符串、布尔值、非有限数字，或实际谱面缺少合法非负定级。

这些项目报告 ERROR 并标为“待人工处理”，不会写进标准副本的 songs 目录。继续扫描其他包以收集完整问题，但本批次无效。可恢复的完整单曲 JSON 报 WARNING 并继续；涉及语义选择的错误不自动修复。

## 背景、编码与诊断

背景先与 `img/bg`、`img/bg/1080` 两处全部文件比较原始名称及归一后的 `.jpg` 名称（不区分大小写）。存在同名文件则跳过并报告 INFO，先于读取尺寸；否则 1920×1440 分流至 `img/bg/1080`，1440×1080 和 1280×960 分流至 `img/bg`。其他尺寸直接 resize 为 1920×1440，不裁剪，再放入 `img/bg/1080` 并报告 INFO。同批新背景同名但内容不同仍报 ERROR。

翻转对应表首次从 active 总 songlist 的曲目及难度条目中明确声明的关系初始化，按无向关系一一配对。配置仍是 JSON 对象，每组只需写一次 `"A": "B"`，A、B 两边都能互推；反向重复项保存时去重。已有明确 inverse 保留；缺少时先查对应表，再尝试 `_light` / `_conflict`。同一背景关联多个不同背景时，整组关系暂不用于推导，记录 WARNING，不静默任选一边或套用后缀；编辑器拒绝应用这种冲突表。旧配置会将冲突保留到 `background_pair_conflicts` 供人工处理，不丢弃冲突信息。配置页可重新读取总表，人工确认配对优先，并同时替换两端原有的自动配对。

扫描全批完成后检查 `bg`、`bg_inverse` 和 `bg_daynight` 引用；既不由本批引入，也不在两个已有目录中的背景报 WARNING，可由后扫描的其他曲目包提供背景。

同一曲目包同时提供两张背景图片，且原始 songlist 明确声明它们的 `bg` / `bg_inverse` 关系时，会发现一组可双向使用的新配对。成功预处理或 01 后自动写入本地配置并报告 INFO；工作区同时保存配对。已有配对和待确认的冲突关系不会被自动覆盖；一对多等歧义报 WARNING。继承值、后缀推导、缺少配套图片或失败批次不作为自动记忆依据。`--scan-only` 仅报告，不修改配置。自动保存只更新背景表，不保存其他尚未保存的界面设置。

图片支持 `.jpg`、`.jpeg`、`.png` 来源，工作副本及派生图统一为真实 JPEG；即使原文件名是 `.jpg`、内部却为 PNG，也会转换。透明区域合成白底。有效 RGB JPEG 在无需调整尺寸时保留原字节，原始包始终不变。音频后缀与实际编码不符时仍不专门识别或修复。

日志统一为三类：INFO 是可自动处理且无需检查的动作，WARNING 是可继续但需人工知悉或审核的动作，ERROR 是无法自动处理的问题。WARNING 不会单独令批次无效；任一 ERROR 都会阻断该批次。预处理通过回调向窗口持续输出日志，各包和总报告均保留结构化诊断、数量与状态。

## 输出与窗口行为

每次运行创建独立批次，不覆盖上次结果：

```text
<发布工作区>/preprocessed-<唯一后缀>/
  report.json             # 原始路径、ID、动作、排除空谱、补全字段、错误与状态
  workspace.json          # 批次归属与原始输入
  songs/
    <id>/                 # 完整处理成功的标准副本
  work/
    <序号>/               # 保留失败过程供诊断；不作为曲目输入
```

报告先以 `complete: false` 写入，每首曲目处理后保存检查点，正常结束后更新为 `true`。曲目全部文件成功处理后才将其目录就位；转码失败不会产生看似完成的半首曲目。源文件和 songlist 在处理前后检查哈希，发现处理中被改动则要求重试。

窗口保留原始待更新路径。当前会话中随后点击“检查资源”，会使用本次标准副本，并带上预处理未解决的问题，避免只检查成功部分后遗漏失败曲目。配置变化后需要重新核验；重启后通过“工作区管理…”选择旧批次并继续处理，会复用哈希校验通过的成功曲目，其余重新生成。旧副本和人工编辑保留在 `work/previous-*`，不会混入新的成功资源集。详见[临时工作区管理](workspaces.md)。

预处理既是可独立使用的辅助入口，也由“01 准备并审核”自动执行；直接运行 01 即可。02 使用工作区中人工审核保存的总表发布。

## 可选命令行

```powershell
# 仅扫描，不写工作副本，也不转码
python -m arcaea_uploader preprocess --config config.local.json --scan-only

# 生成标准副本和报告
python -m arcaea_uploader preprocess --config config.local.json
```

需要输入目录、输出工作区和非空 `import.version`；不要求 VPS 或本地服务端已经配置。active 总表可选，存在时用于精确补全和背景对应表初始化；已有服务端路径用于判断哪些难度已经有实际谱面。退出码 0 表示存在可用曲目且没有 ERROR，1 表示有 ERROR 或没有有效曲目，2 表示配置/总表无效。
