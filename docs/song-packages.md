# 曲目包与增量规则

依据用户 2026-11-05 补充的工作流。以下描述标准曲目包与后续发布规则；来源不符合标准时，先使用[曲目预处理](preprocessing.md)生成工作副本。当前已实现预处理和只读资源预检。

## 输入目录

标准输入根目录中，每首曲目位于直接子目录；目录名与 songlist 内 `id` 一致，不加 `dl_`。原始收集目录则允许外层曲名、内层英文名等嵌套形式，预处理优先按 songlist.id 生成这里的标准结构。

```text
incoming/
  new_song/
    2.aff
    base.ogg
    base.jpg
    base_256.jpg
    songlist.json
    custom_bg.jpg        # 可选
    video_1080.mp4       # 可选
  existing_song/
    3.aff
    songlist            # 可以只描述新增难度
```

完整新曲目的标准资源：

- 至少一个 `0.aff` 至 `4.aff`，可以有多个。
- `base.ogg`；少数曲目还有 `0.ogg` 至 `4.ogg` 独立音频。
- `base.jpg` 和 `base_256.jpg`；少数曲目还有数字 `.jpg` 与数字 `_256.jpg` 独立曲绘。
- 一份 JSON 格式 songlist，文件名为 `songlist`、`songlist.txt` 或 `songlist.json`。
- 可选额外 JPG 背景、`video_1080.mp4`。

已有曲目提交的是补丁，允许不带完整音频和曲绘；不得因为本次输入缺少文件就删除原有文件。预检会提示缺少的旧资源，新曲目缺少基础资源则报告错误。

资源预检要求一个文件夹只有一份 songlist、只描述该文件夹对应的一首曲目；接受 `{"songs":[...]}`、单曲对象或单曲数组，兼容可恢复的完整单曲 JSON（WARNING）。预检不递归整理原始嵌套结构，该步骤交由预处理完成。默认空 AFF 文件排除，保留已声明的占位难度；非资源文件按 INFO 提示忽略。无效或缺失 ID 为 ERROR，不从目录名猜测。

## songlist 合并

总表为资源包 `songs/songlist`。本地提供的 `songlist.html` 实际是维基格式的字段说明，已参考其 `idx`、`id`、`ratingClass`、预览、背景与媒体字段。

- 按 `id` 识别曲目。新曲目追加到总表，忽略输入 `idx`，依次使用当前最大 `idx + 1`；已有曲目的 `idx` 不变。
- 当前导入统一走远程下载曲目布局，使用 `dl_<id>` 并将导入条目 `remote_dl` 设为 `true`。已有本体曲迁移仍需额外核验，不能仅靠改目录完成。
- `import.version` 为必填的本次导入版本，覆盖所有触及曲目顶层的 version，包括缺失值；不新增或覆盖难度 version，未导入的曲目不变。该字段不是 bundle 文件名或客户端版本。
- 普通对象保留未提交的字段；新字段自动补入。
- `difficulties` 按 `ratingClass`（0–4）合并，新增难度追加，未提交的难度保留。不能直接替换数组，也不能把数组下标当作难度。
- 普通字段或同一难度字段存在不同值时，保留总表值，记录旧值、新值和字段路径，报告 WARNING，由人决定最终内容。version、remote_dl 和无实际谱面的 rating 按明确规则统一处理。自动合并结果只是审核草案。
- 没有实际谱面的已声明 ratingClass，rating 统一为 0；实际谱面同时检查本批输入和已有服务端，排除纯 timing 占位。输入占位条目不会覆盖旧真实谱面的描述，不自动声明不存在的难度。rating 非合法数字为 ERROR。
- 翻转对应表从现有总表初始化并可在配置页维护；每组无向关系只写一次，两边均可互推。保留明确给出的 bg_inverse，缺少时优先查表，再尝试 `_light` / `_conflict` 后缀。一对多的整组关系不自动选择，有歧义或未知对应报 WARNING。
- 不重新编号旧曲目，不更改 `packlist`、`unlocks` 或 `songs/pack`，不在下载目录中复制每首曲目的独立 songlist。

总表重复 ID 或非法难度会阻止合并；重复 idx 则保留原编号并列入审核报告，仍生成草案。实际本地总表已发现此类重复，工具不会自行修复。空表首个 idx 为 0。普通数组的覆盖/合并不作猜测；不同值列为冲突。

## bundle 资源准备

资源包保留既有 `char/`、`img/`、`songs/`、`tl/` 和增量历史，在现有内容上更新。绝不能用仅有本次新增资源的目录直接打包，否则历史资源可能被 Bundler 判成移除。

曲目曲绘和用于生成预览的 OGG 合入 `songs/dl_<id>/`。这里的「只保留」约束本次从原始包导入的文件类型，不表示删除已有目录中未提交的资源。AFF、每曲 songlist、视频不进入此目录。额外背景单独分流至 `img/bg`，预检按此约定列出目标。

| 额外背景尺寸（宽×高） | 目标位置 | 文件名 |
| --- | --- | --- |
| 1920×1440 | `img/bg/1080/` | 保留原名 |
| 1440×1080 | `img/bg/` | 保留原名 |
| 1280×960 | `img/bg/` | 保留原名 |
| 其他尺寸 | 待人工处理 | 阻止该批次发布 |

曲绘按 `base.jpg`、`base_256.jpg`、`0–4.jpg`、`0–4_256.jpg` 文件名识别，其他 JPG 视为背景。先检查两个已有 bg 目录中的全体文件，完整文件名已存在则跳过导入并报告 INFO，不读取该输入图片的尺寸；再对新背景分流。1920×1200 当前属于新尺寸，报 ERROR。同批新背景同名但内容不同报 ERROR。songlist 中的背景若既非本批新增，也不在已有两目录中，报 WARNING。

已核对的现有脚本行为：`base.jpg → 1080_base.jpg`，缩略图目标尺寸 384×384，`base_256.jpg → 1080_base_256.jpg`；从 `audioPreview` 到 `audioPreviewEnd`（毫秒）裁剪预览，默认淡入 500ms、淡出 2000ms，成功后删除 bundle 工作副本中的完整音频。服务端完整音频及原始包保留。

01/02 将 `base.ogg` 派生为 `preview.ogg`，数字音频派生为 `<数字>_preview.ogg`，完整音频仅保留于下载侧。音频与预览区间均未变时复用已有预览，人工修改区间后从完整音频重建。独立曲绘沿用数字文件名。`0/1/2/4.ogg` 与客户端及原服务端的完整兼容仍需确认，预检报告 WARNING；原服务端只特殊处理 `3.ogg`，其余可能需要人工补充下载声明。工具原状见[工具调查](existing-tools.md)。只读预检列出媒体准备任务，最终文件和哈希由 01/02 确定。

## 服务端下载资源

目标是本地服务端 `latest version/database/songs/<id>/`，不加 `dl_`。只导入数字 AFF、完整 OGG 和可选 `video_1080.mp4`。

AFF `arc` 事件中的 `*_wav` 特殊音效，以及已存在主音频时的额外 WAV，均不进入 bundle 或服务端 songs，报告 WARNING 交给人工处理；AFF 内的引用不修改。规范命名的完整 base.wav / 数字.wav 若不是特殊音效，仍可通过预处理转为 OGG。后缀与实际编码不符的文件按 README 的既定策略原样处理。

依次检查 `0.aff`、`1.aff`、`2.aff`：输入有真实谱面则使用输入；输入没有但已有服务端谱面则保留；两处都没有才复制占位谱面。占位源可配置，默认推导与示例使用 `sayonarahatsukoi/0.aff`。不为 3、4 难度自动补占位，也不自动添加 songlist 中的虚构难度。

例：已有 `2.aff`，输入只有 `3.aff` 和相应 songlist 补丁。合并后保留旧 `2.aff`，新增真实 `3.aff`，仅为缺失的 0、1 补占位；songlist 保留原难度并新增 ratingClass 3。

当前不自动同步服务端 `songs/songlist`：用户本次只要求更新 bundle 总表，已有服务端默认该位置也未发现总表。将来若下载权限/视频声明依赖此文件，应作为明确选项处理。存在视频但合并后的 songlist 没有相应 `additional_files` 声明时，预检提示审核，不擅自编造条目。

## VPS 发布单位

发布包含新生成的 `.cb + .json` 和本次新增/变更的下载文件，也包括既有曲目新增的难度。不能只按「新曲目目录」筛选上传。传输不得删除远端已有资源，bundle 数据全部到位后才发布配套元数据，再刷新曲目与 bundle 缓存。

新生成的两个文件使用同一前缀。普通更新等于配套 JSON 的 `versionNumber`，例如 `7.0.256.5.cb` 与 `7.0.256.5.json`；切换应用版本或首次构建时，JSON 两个版本字段均为新应用版本，文件名加 `.0`，例如 `7.0.257.0.cb/.json` 内记录 `7.0.257`。承接包仍指向上一包，之后继续递增为 `.1`。版本链由元数据决定，曲目导入 version 与应用版本独立。
