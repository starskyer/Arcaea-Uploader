# 桌面界面

产品以类似常用签名工具的紧凑桌面窗口为主入口，命令行保留给调试与自动化。当前通过 Python 自带 Tkinter/ttk 实现，资源规划与配置逻辑独立于界面，后续执行流程可接入相同业务层。

## 更新页

顶部选择本次来源目录并填写“本次导入 version”，点击“预处理曲目”生成标准工作副本，再点击“检查资源”运行只读预检。version 必填，用于覆盖本次曲目及其声明难度的原始 version，不影响未导入曲目，也不代表 bundle 文件名。两个操作均在后台执行，窗口可以切换页面；处理期间改了配置，结果会标为过期。原始路径保持不变，当前会话使用与配置匹配的标准副本检查；预处理错误一并进入检查报告，不能只因部分曲目成功就忽略其他曲目。具体见[预处理规则](preprocessing.md)。

“沿用当前应用版本”默认勾选，从选定 active 的 `metadata.oldjson` 中读取最高 bundle 版本所对应的应用版本，输入框锁定显示该值，并预览下一包名称。取消勾选后输入框可编辑，填写新应用版本，预览显示 `<新应用版本>.0.cb / .json`。两页的勾选状态与输入内容同步；重新勾选不会丢失手动输入草稿。

切换应用版本时，JSON 的 `applicationVersionNumber` 和 `versionNumber` 都使用新版本本身，文件名加 `.0`；`previousVersionNumber` 衔接原有最新包。再次勾选沿用后继续递增为 `.1`。尚无历史时提示首次构建前填写应用版本，仍可进行曲目预处理；应用版本格式无效时在信息日志报告 ERROR。

中间两个阶段入口为“准备并审核”和“发布更新”，交互遵循[两步流程](update-workflow.md)。当前两者禁用并显示“待接入”，不会模拟已经完成准备或发布。结果按曲目、资源变更、信息日志分栏，报告可导出为 JSON。日志以 INFO / WARNING / ERROR 分色滚动并统计数量：INFO 可自动处理且无需人工检查，WARNING 可继续但需人工知悉或审核，ERROR 无法自动处理并阻断批次。预处理期间持续显示日志；WARNING 本身不令批次无效。

后续第一步完成时打开本次 songlist 供人工审核；第二步由用户点击触发，不能因关闭编辑器自动发布。耗时任务继续采用后台执行，状态和错误在窗口内呈现。

## 配置页

所有设置在一页内分组滚动显示，底部保留载入、另存和保存按钮。

| 分组 | 内容 |
| --- | --- |
| 本次导入 | 与更新页同步的 version |
| Bundle 应用版本 | 默认沿用历史应用版本；取消勾选可填写新版本，并预览承接包名 |
| 本地资源 | 服务端根目录、active、输入曲目目录、发布工作区 |
| VPS / SSH | IP 或主机名、端口（默认 22）、用户名、远端项目根目录、私钥、known_hosts |
| 刷新 API | API 基址、Token 环境变量名 |
| 工具与目录细节 | database 相对路径、占位谱面覆盖、FFmpeg、远端 database 相对路径 |

Bundler 与图片/预览处理代码已内置，无需填写这两个路径，也无需下载外部 Bundler 项目。旧配置中的相关路径在载入时忽略，保存时移除。FFmpeg 仍由用户安装，留空时从 PATH 查找，也可指定可执行文件。占位谱面留空时，按本地服务端根目录和 database 相对路径推导 `songs/aletheia/0.aff`。窗口的两阶段按钮尚未接入这些模块，网络设置也仅保存。

“背景对应表…”以 JSON 对象保存无向的一一配对关系：只需写一次 `"A": "B"`，两边均可推导，反向重复项自动去重。首次配置 active 后从其 `songs/songlist` 初始化，不要求从空表录入；只有各层明确声明的 inverse 作为证据，不把继承关系误判为新特例。可以编辑特例或“重新读取当前总表”，应用后再保存配置。重新读取会替换编辑区草稿；关闭而未应用不会修改当前配置。同一背景关联多个背景时整组留待确认，编辑器拒绝应用冲突表，导入日志报告 WARNING；人工指定配对同时覆盖两端已有的自动配对。

右上角“关于与授权”展示 Bundler 作者、上游地址及完整 MIT 许可证，从随包资源读取，不依赖网络或原始工程目录。

本地相对路径在载入时以配置所在目录解析；另存到其他目录时保留原路径含义。远端 POSIX 路径原样保存。端口不合法时拒绝保存，保留此前文件；正常保存采用临时文件替换。未填写完的路径可先保存，预检阶段再校验存在性。

配置文件中的 `bundle.follow_app_version` 是 JSON 布尔值，默认 `true`；`bundle.app_version` 保存手动版本草稿，沿用模式下不使用该草稿。旧配置缺少 `bundle` 组时自动采用默认值，保存配置后写入文件。

## 启动与配置位置

- Windows `.pyw` 文件关联正常时，双击 `Arcaea-Uploader.pyw`。
- Windows 便携版完整解压后运行 `Arcaea-Uploader.exe`，不依赖本机 Python；保留 `_internal` 目录。
- 安装项目后可运行无控制台入口 `arcaea-uploader-gui`。
- `python -m arcaea_uploader` 默认打开窗口；`gui --config` 支持指定配置。
- 开发时优先使用项目中被忽略的 `config.local.json`；不存在时使用 `%LOCALAPPDATA%/Arcaea-Uploader/config.json`（其他平台使用相应用户配置目录）。

默认窗口为 920×700 个逻辑像素，可调整大小，按系统 DPI 缩放。已在本机 200% 缩放环境检查更新页、配置页顶部及底部布局。源码运行需要 Python、Tkinter 和 Pillow；Windows 便携版包含这些运行时，FFmpeg 仍需自行安装或指定。
