# 桌面界面

产品以类似常用签名工具的紧凑桌面窗口为主入口，命令行保留给调试与自动化。当前通过 Python 自带 Tkinter/ttk 实现，资源规划、准备发布与配置逻辑独立于界面，三个阶段共用业务层。

## 更新页

流程：选择目录和 version → 01 准备审核 → 人工保存 → 02 打包上传 → 03 操作 → 确认提交。01 包含预处理和检查，02 上传后保留工作区；03 的 API 操作按需选择，最终提交入口在下方结果区。

01、02 已接入，可直接选择目录、填写 version、执行 01，不必先点辅助按钮。“预处理曲目”可单独生成标准工作副本；“检查资源”可单独运行只读预检。version 必填，用于覆盖本次曲目顶层的原始 version，不会新增或覆盖难度 version；不影响未导入曲目，也不代表 bundle 文件名。

两个辅助操作均在后台执行，窗口可以切换页面；处理期间改了配置，结果会标为过期。原始路径保持不变，当前会话使用与配置匹配的标准副本检查，无需把标准副本搬回原目录。预处理错误一并进入检查报告，不能只因部分曲目成功就忽略其他曲目。具体见[预处理规则](preprocessing.md)。

“沿用当前应用版本”默认勾选，从选定 active 的 `metadata.oldjson` 中读取最高 bundle 版本所对应的应用版本，输入框锁定显示该值，并预览下一包名称。取消勾选后输入框可编辑，填写新应用版本，预览显示 `<新应用版本>.0.cb / .json`。两页的勾选状态与输入内容同步；重新勾选不会丢失手动输入草稿。

切换应用版本时，JSON 的 `applicationVersionNumber` 和 `versionNumber` 都使用新版本本身，文件名加 `.0`；`previousVersionNumber` 衔接原有最新包。再次勾选沿用后继续递增为 `.1`。尚无历史时提示首次构建前填写应用版本，仍可进行曲目预处理；应用版本格式无效时在信息日志报告 ERROR。

中间三个阶段遵循[更新流程](update-workflow.md)。01 生成工作区审核副本；02 在确认审核保存后打包并上传；03 打开下方“03 · 定数与服务端”，也可对已手动上传的批次单独执行。其他结果按曲目、资源变更、信息日志分栏，可导出 JSON。日志使用 INFO/WARNING/ERROR，原批次 ERROR 不能只因选择了成功子集而被忽略。上下标签页选中时仅改变颜色，保持形状和尺寸。

03 页双击真实难度填写一位小数定数，空难度固定 -1；通过“审核总表…”选择最终上传用的 songlist，通过“选项…”选择 API 阶段。执行时提示未填定数并确认上传情况；独立任务保存与重试见[03 服务端操作](server-operations.md)。

“购买项预览”支持双击编辑本批 ID、单曲/曲包类型和价格，也可选择跳过或恢复自动推导。编辑只保存本批任务，不改 songlist；合并曲包项的修改应用到它的全部引用曲目。执行前会列出无法推断和人工跳过的条目，取消不发送请求，确认后以 WARNING 记录跳过并继续其他操作。

工作区提交清理后，03 显示只读归档，仍可查看和导出，编辑、执行与提交按钮禁用。“创建后续任务…”会另存独立草稿，保留原记录，默认关闭资源刷新；修改定数或购买安排后再明确执行，新任务成功后自动归档。载入旧版本的已提交任务也保持只读。

第一步完成时用记事本打开本批工作区的 songlist 供人工审核；第二步由用户点击并确认保存后触发，不能因关闭编辑器自动发布。耗时任务在后台执行，状态和错误在窗口内呈现。发布时选项以任务启动时为准；过程中修改配置不会改变正在执行的任务。

尚未打包时，再次 01 默认追加到当前批次：支持换目录补新曲、同曲加难度或重扫原目录，保留已准备内容和已保存的人工修改，总表路径与已有 idx 保持不变。追加前会提醒保存并关闭编辑器。底部“新建批次…”明确开始独立工作区，不删除旧批次。构建前可调整导入 version，逐曲审核优先保留，应用版本选项须一致；追加 ERROR 解决前不能执行 02，开始构建后也不能再追加。

## 配置页

所有设置在一页内分组滚动显示，底部保留载入、另存和保存按钮。每个配置项及背景对应表旁都有可点击的 **ⓘ**，说明用途、何时填写及具体示例；更新页的目录、version、应用版本与流程也有对应说明。说明窗口可选中文本复制，支持滚动、调整大小和 Esc 关闭，不会改动配置或执行任务。示例使用占位路径、域名和 Token，需换成自己的实际值。

| 分组 | 内容 |
| --- | --- |
| 本次导入 | 与更新页同步的 version |
| Bundle 应用版本 | 默认沿用历史应用版本；取消勾选可填写新版本，并预览承接包名 |
| 本地资源 | 服务端根目录、active、输入曲目目录、发布工作区 |
| VPS / SSH | IP 或主机名、端口（默认 22）、用户名、远端项目根目录、私钥、known_hosts |
| 管理 API | 03 使用的 API 基址、Token 环境变量名、是否使用系统代理；取消勾选可单独直连 |
| 工具与目录细节 | database 相对路径、占位谱面覆盖、FFmpeg、远端 database 相对路径 |

Bundler、图片/预览处理与 SSH/SFTP 客户端已内置，无需填写外部脚本路径。旧配置中的相关路径在载入时忽略，保存时移除。FFmpeg 仍由用户安装，留空时从 PATH 查找，也可指定可执行文件。占位谱面留空时，按本地服务端根目录和 database 相对路径推导 `songs/sayonarahatsukoi/0.aff`，与示例配置一致。SSH 用于 02 上传，管理 API 用于 03；02 不需要 API Token。

SSH 连接设置对应此前使用 SCP 传文件时的主机、账户、端口和私钥。API 用于上传完成后让运行中的服务端刷新资源索引，基址一般填写 `https://arc.example.com/api/v1`；二者用途不同。`token_env` 填本机环境变量的**名称**，例如 `ARCAEA_UPLOADER_API_TOKEN`，实际管理 Token 放在该变量的值中，03 通过 HTTP `Token` 请求头发送。该值来自服务端 `API_TOKEN` 或具有 `system` 权限的 API 用户，与 SSH 登录凭据分别管理。环境变量需对启动 Uploader 的进程可见；从 PowerShell 临时设置时，要从同一窗口启动程序。当前预处理和检查不要求 API 配置或 Token。

项目自带的旧 Web 管理页使用 Cookie/session 登录，与上述 Token 请求头分别鉴权；网页能刷新不代表已经配置 API Token。概念与只读验证示例见 [API 鉴权说明](api-auth.md)。

更新页底部的“工作区管理…”列出各 server 的未提交批次，支持恢复整套配置与进度、打开目录或明确放弃。启动时主动提示未完成工作；选择新目录时确认是累积还是另建工作区。02 上传后仍保留资源、定数和购买候选；03 成功且人工确认提交后才清理，具体见[工作区管理](workspaces.md)。

“背景对应表…”以 JSON 对象保存无向的一一配对关系：只需写一次 `"A": "B"`，两边均可推导，反向重复项自动去重。首次配置 active 后从其 `songs/songlist` 初始化，不要求从空表录入；只有各层明确声明的 inverse 作为证据，不把继承关系误判为新特例。可以编辑特例或“重新读取当前总表”，应用后再保存配置。重新读取会替换编辑区草稿；关闭而未应用不会修改当前配置。同一背景关联多个背景时整组留待确认，编辑器拒绝应用冲突表，导入日志报告 WARNING；人工指定配对同时覆盖两端已有的自动配对。

右上角“关于与授权”展示 Bundler 作者、上游地址及完整 MIT 许可证，从随包资源读取，不依赖网络或原始工程目录。

01 或预处理成功后，若原曲目包明确声明新背景配对且同时提供两张图片，会自动将新关系保存到本地背景表并显示 INFO；工作区也会记忆该配对。保存只涉及背景表，不会一并保存其他尚未保存的设置。冲突保留已有关系并提醒确认，失败和只读扫描不写配置。非标准背景尺寸直接缩放为 1920×1440 后放入 `img/bg/1080`。

本地相对路径在载入时以配置所在目录解析；另存到其他目录时保留原路径含义。远端 POSIX 路径原样保存。端口不合法时拒绝保存，保留此前文件；正常保存采用临时文件替换。未填写完的路径可先保存，预检阶段再校验存在性。

配置文件中的 `bundle.follow_app_version` 是 JSON 布尔值，默认 `true`；`bundle.app_version` 保存手动版本草稿，沿用模式下不使用该草稿。旧配置缺少 `bundle` 组时自动采用默认值，保存配置后写入文件。

## 启动与配置位置

- Windows `.pyw` 文件关联正常时，双击 `Arcaea-Uploader.pyw`。
- Windows 便携版完整解压后运行 `Arcaea-Uploader.exe`，不依赖本机 Python；保留 `_internal` 目录。
- 安装项目后可运行无控制台入口 `arcaea-uploader-gui`。
- `python -m arcaea_uploader` 默认打开窗口；`gui --config` 支持指定配置。
- 开发时优先使用项目中被忽略的 `config.local.json`；不存在时使用 `%LOCALAPPDATA%/Arcaea-Uploader/config.json`（其他平台使用相应用户配置目录）。

默认窗口为 920×700 个逻辑像素，可调整大小，按系统 DPI 缩放；最小高度会根据字体尺寸为结果区预留空间。已在本机 200% 缩放环境检查更新页、配置页顶部及底部布局，并以 100% 字体缩放检查最小窗口与说明窗口。源码运行需要 Python、Tkinter 及项目声明的依赖；Windows 便携版包含运行时，FFmpeg 仍需自行安装或指定。
